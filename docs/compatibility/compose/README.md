# Jetpack Compose API coverage

Which Jetpack Compose (Kotlin) APIs SimCore can run, for Android apps written natively rather than with Expo.
**Preview:** a JVM guest runs the real Compose runtime with SimCore's own UI libraries
([frameworks/compose](../../../frameworks/compose/README.md)); rows are marked as they land. The area files list every
public API of the Compose libraries an app typically uses: one row per composable, `Modifier` extension, other
top-level function and top-level type (overloads share a row; members such as `ButtonDefaults.shape` are
covered by their type's row). They are generated from AndroidX's published API signature files, newest release
per library; the versions are in the [support matrix](../README.md#versions).

Pick any row to work on: open an
[API request issue](https://github.com/MitchellSPeterson/SimCore/issues/new?template=api-request.yml) for it
(or take an existing one), and link the issue in the row's **Issue** column.

| Status | Meaning | Score |
|---|---|---|
| ✅ | Implemented: behaves as on a device | 1 |
| 🟠 | Partial: works, with known gaps listed in Notes | ½ |
| ⬜ | Planned: not started | 0 |

Compose here means Android only (Compose Multiplatform on iOS is not tracked). Most apps use a small slice of
these APIs; [composables.md](composables.md), [modifiers.md](modifiers.md) and [runtime.md](runtime.md) are
the ones that matter most. Notes mark APIs that are `Deprecated` or `Experimental` (opt-in) upstream.

## How Android support works

Apps compile unchanged against SimCore's reimplementation of `androidx.compose.ui` / `foundation` / `material3` with the
real `androidx.compose.runtime`, run as a guest process and send layout primitives plus Modifier chains to the host
(protocol section K), which lays them out with Compose's measure/place rules in whole device pixels. Rendering is
checked against a real APK of the same examples on the Android 17 emulator (`scripts/compare-android.sh`, every state
< 2% of pixels). The Expo / React Native Android column ([expo/](../expo/README.md)) will
share the Android host work (device profile, status bar, Roboto).

## Adding or changing a row

- Implementing an API: set the row's status (and Notes for 🟠) and run `node scripts/api-coverage.mjs`.
- New Compose release: `node scripts/compose-inventory.mjs` (needs network) regenerates the area files from the
  newest signature file of each library listed in `LIBS` in that script. It keeps every existing row's status,
  issue and notes and adds new APIs as ⬜. Then run `node scripts/api-coverage.mjs`.
- Another AndroidX library apps rely on (e.g. `lifecycle-runtime-compose`): add it to `LIBS` and regenerate.
